# MA50-бот для Bybit Spot

Бот держит BTC, пока дневное закрытие выше 50-дневной средней, и сидит в USDT, когда ниже.

**Правила**
- Раз в сутки, после закрытия дневной свечи Bybit (00:00 UTC), бот сравнивает цену закрытия с MA50 — средней ценой закрытия за 50 дней.
- **Закрытие выше MA50** → должны быть в BTC. Если бот в USDT, он покупает на весь свободный USDT субаккаунта (с лимитом).
- **Закрытие не выше MA50** → должны быть в USDT. Если бот в BTC, он продаёт весь BTC.
- Ордер уходит примерно в 00:05 UTC (03:05 МСК): по рынку или, если включено, лимитным ордером (см. раздел «Режим исполнения»). Целей, стопов и докупок нет.

Бэктест на данных Bybit (комиссия 0,1%):

| Период | MA50 | Купить и держать |
|---|---|---|
| 30.11.2025 – 22.11.2026 | +14,7%, 10 входов, просадка 17,8% | −32,7% |
| 21.04.2024 – 22.11.2026 | +52,1%, 29 входов, просадка 25,5% | ≈ 0% |

Доходность сильно зависит от нескольких крупных трендов. В прошлом прибыльными были лишь 2–3 сделки из 10, остальные — мелкие убытки. Реальный результат может заметно отличаться от бэктеста.

## 1. Установка (локально)

1. Установите [Bun](https://bun.sh):
   - macOS / Linux: `curl -fsSL https://bun.sh/install | bash`
   - Windows (PowerShell): `powershell -c "irm bun.sh/install.ps1 | iex"`
2. В папке проекта:
   ```bash
   bun install
   cp config.example.json config.json
   cp .env.example .env
   bun test            # 15 тестов на фейковой бирже должны пройти
   ```
   Если `bun install` напишет `Blocked 1 postinstall`, это нормально.

## 2. Этап 1: бумажная торговля (без ключей)

В `config.json` оставьте `"mode": "paper"`. Бот берёт реальные цены Bybit, но торгует виртуальными `paperStartQuote` (по умолчанию $1 000) и ордеров не отправляет.

```bash
bun run backtest          # MA50 за последний год на данных Bybit + список сделок
bun run backtest -- --days 900
bun run status            # текущий сигнал, MA50, баланс, позиция
bun start                 # работать постоянно (Ctrl+C - остановка)
```

Сейчас (конец ноября 2026) сигнал «держать USDT», поэтому бот будет ждать. Каждую ночь после 00:05 UTC он пишет строку в лог и (если включено) присылает отчёт в Telegram. Сделки в бумажном режиме будут, когда цена пересечёт MA50. Как бот вёл бы себя в прошлом, показывает `bun run backtest`.

## 3. Этап 2: тестнет Bybit (настоящие ордера, тестовые деньги)

1. Зарегистрируйтесь на [testnet.bybit.com](https://testnet.bybit.com) (отдельный аккаунт, не связанный с основным) и запросите тестовые USDT в разделе активов.
2. Создайте там API-ключ (см. права ниже) и впишите его в `.env`:
   ```
   BYBIT_API_KEY=...
   BYBIT_API_SECRET=...
   ```
3. В `config.json`: `"mode": "testnet"`.
4. `bun run status`: должен показать тестовый баланс.
5. Проверка покупки и продажи без ожидания сигнала. На тестнете можно временно поставить `"maPeriod": 2` или `3`, чтобы сигнал менялся чаще, и запустить `bun run once -- --force`. Флаг `--force` исполняет текущий сигнал, даже если день уже обработан. Потом верните 50.

## 4. Этап 3: боевой режим

1. **Субаккаунт Bybit.** Создайте субаккаунт в разделе субаккаунтов и переведите на него USDT.
2. **API-ключ на субаккаунте:**
   - тип: системный (HMAC);
   - права: **Чтение и запись**, только **Spot → Trade** (торговля на споте);
   - **без** Withdrawal (вывод) и Transfer (переводы);
   - **IP-ограничение:** на VPS обязательно укажите IP сервера. Локально домашний IP обычно меняется, поэтому ключ без привязки к IP держите только на время проверки.
3. Впишите ключ в `.env`, в `config.json` поставьте `"mode": "live"`.
4. `bun run status` → проверьте баланс и сигнал → `bun start`.

## 5. Telegram (по желанию)

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен.
2. Напишите своему боту любое сообщение, откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id": ...}`.
3. В `.env`:
   ```
   TELEGRAM_TOKEN=...
   TELEGRAM_CHAT_ID=...
   ```

Бот присылает сообщения о запуске, покупке и продаже (с ценой и суммой), срабатывании лимита, исполнении с опозданием и ошибках. Если `telegramDailyReport: true`, ещё и короткий ежедневный отчёт. В режимах paper и testnet у сообщений есть префикс `[PAPER]` / `[TESTNET]`.

## 6. Настройки `config.json`

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `mode` | `paper` | `paper` / `testnet` / `live` |
| `symbol` | `BTC/USDT` | торговая пара |
| `maPeriod` | `50` | период средней, дней |
| `sizing` | `all` | `all` — весь свободный USDT; `fixed` — `fixedAmountQuote` |
| `fixedAmountQuote` | `1000` | сумма покупки при `sizing: fixed` |
| `reservePct` | `0.5` | сколько % USDT оставить на комиссию/округление |
| `maxOrderQuote` | `3000` | **лимит одной покупки**; остаток остаётся в USDT и приходит предупреждение. `0` — без лимита |
| `minPositionQuote` | `10` | меньше этой суммы в BTC считается «пылью», не позицией |
| `checkIntervalMinutes` | `15` | как часто бот просыпается в режиме `run` |
| `executionDelayMinutes` | `5` | через сколько минут после 00:00 UTC действовать |
| `paperStartQuote` | `1000` | виртуальный баланс для `paper` |
| `feePct` | `0.1` | комиссия для `paper` и `backtest` |
| `execution` | `market` | `market` — рыночный ордер сразу; `limit` — лимитка с переходом на рынок |
| `limitOffsetPct` | `0.3` | на сколько % лучше текущей цены ставить лимитку |
| `limitTimeoutHours` | `4` | сколько часов ждать лимитку, потом остаток по рынку |
| `telegramDailyReport` | `true` | ежедневный отчёт в Telegram |
| `dataDir` | `data` | папка для состояния, журнала и лога |

Ключи Bybit и Telegram хранятся только в `.env`. Файлы `.env` и `config.json` исключены из git.

## 6a. Режим исполнения: рынок или лимитка

Сигнал в обоих режимах один и тот же. Отличается только то, как бот покупает или продаёт после сигнала.

- **`"execution": "market"`** (по умолчанию): сразу рыночный ордер.
- **`"execution": "limit"`**:
  1. Бот выставляет лимитный ордер на `limitOffsetPct` (0,3%) лучше текущей цены: на покупку ниже, на продажу выше.
  2. При каждой проверке (раз в `checkIntervalMinutes`) смотрит, исполнился ли ордер.
  3. Если за `limitTimeoutHours` (4 ч) ордер не исполнился или исполнился частично, бот отменяет остаток и добирает его по рынку.
  4. Итоговое уведомление показывает, как прошла сделка: лимиткой, частично или по рынку.

В бэктесте на данных Bybit лимитный режим дал за последний год +18,2% вместо +14,7%, за 2,6 года +59,4% вместо +52,1%. Лимитка исполнялась примерно в 2/3 случаев, средняя экономия около 0,1% на сделку. Это улучшение исполнения, а не стратегии, и в реальности выигрыш может быть меньше.

Открытый лимитный ордер хранится в `data/state-<режим>.json`. Если бот перезапустить, он продолжит следить за ордером. Файл `STOP` при открытом ордере отменяет его без добора остатка.

Включать лимитный режим лучше после проверки на тестнете.

## 7. Повседневное управление

| Что нужно | Как |
|---|---|
| Посмотреть состояние | `bun run status` |
| **Экстренно остановить торговлю** | создать пустой файл `STOP` в папке проекта. Бот продолжит работать и сообщать сигналы, но не будет торговать. Удалить `STOP` → при следующей проверке бот исполнит текущий сигнал |
| Остановить бота | Ctrl+C (или `systemctl stop` на сервере) |
| Пополнить или вывести | перевести USDT на субаккаунт или с него, лучше когда бот в USDT |
| История сделок | `data/trades.csv` |
| Лог | `data/bot.log` |
| Состояние | `data/state-<режим>.json` (у каждого режима своё) |

**Если бот был выключен** (компьютер спал в 00:05 UTC): при следующем запуске он сразу приведёт позицию к текущему сигналу и отметит в уведомлении, на сколько часов опоздал. Задержка в несколько часов на результат почти не влияет, задержка в дни — влияет.

**Если ордер не прошёл** (нет сети, ошибка биржи): день не помечается обработанным, бот повторит попытку через `checkIntervalMinutes` и сообщит об ошибке в Telegram.

**Не трогайте вручную ордера и баланс субаккаунта, пока бот работает.** Бот определяет позицию и считает итог сделки по балансам. Ручные сделки или переводы во время открытой лимитки исказят расчёт.

## 8. Перенос на VPS (позже)

Подойдёт любой Linux-сервер за $4–6 в месяц. Установите Bun, скопируйте папку проекта (с `config.json` и `.env`), выполните `bun install`, затем создайте сервис `/etc/systemd/system/ma-bot.service`:

```ini
[Unit]
Description=Bybit MA50 bot
After=network-online.target

[Service]
WorkingDirectory=/home/USER/ma-bot
ExecStart=/home/USER/.bun/bin/bun run src/main.ts run
Restart=always
RestartSec=30
User=USER

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now ma-bot
journalctl -u ma-bot -f      # смотреть лог
```

Не забудьте привязать API-ключ к IP сервера.

## 9. Запуск на Node.js вместо Bun

Код не зависит от Bun. На Node 20+: `npm install`, затем `npx tsx src/main.ts run`. Переменные из `.env` при этом нужно загрузить самостоятельно, например `node --env-file=.env --import tsx src/main.ts run`. Тесты написаны для `bun test`.

## Структура

```
src/strategy.ts   логика стратегии (сигнал, размер ордера, бэктест) — без сети
src/bot.ts        конфиг, состояние, Telegram, брокеры (paper / биржа), одна проверка
src/main.ts       команды run / once / status / backtest
tests/            тесты на фейковой бирже
```
